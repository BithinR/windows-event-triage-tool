How to Think Like a SOC Analyst

“One security event rarely tells the entire story. Analysts build context by correlating multiple events.”

  1. Identify the event. What Event ID is it, and what does it normally mean?
  2. Understand what happened. Read the details: who, what, when, and from where.
  3. Identify the affected user or system. Which account or computer is involved?
  4. Determine whether the activity is expected. Is this routine for this user, machine, and time of day?
  5. Look for related events. Are there other events nearby that add context?
  6. Correlate authentication and privilege activity. Did failures lead to success? Was a new account given power?
  7. Gather additional evidence. Check other telemetry (endpoint, MFA, firewall) if available.
  8. Decide whether escalation is required. Is this worth raising with the team?

“A detection is a reason to investigate, not proof that an attacker is present.”

Windows Event Viewer Instructions

  1. Open Windows Event Viewer.
  2. Navigate to Windows Logs → Security.
  3. Select or filter the events you want to investigate.
  4. Export the events to CSV (see the README for the recommended method that includes the Message text).
  5. Upload the CSV into this tool below.

            Event ID Reference (Beginner Cheat Sheet)

            A short plain-English guide to the events this tool recognises.

            Event IDNameWhat it means
            4624Successful logonA user or service signed in successfully. Useful context, rarely suspicious on its own.
            4625Failed logonA login attempt was rejected. One is usually nothing; many in a row deserve a closer look.
            4688Process createdA program was started. Useful for understanding what ran, but not a detection by itself.
            4720User account createdA new account was made. Often routine, but should be verified.
            4726User account deletedAn account was removed. Can be normal cleanup or an attacker covering tracks.
            4728Added to global security groupA user joined a domain group. Privileged groups deserve extra attention.
            4732Added to local security groupA user joined a machine-local group, like Administrators.
            1102Security audit log clearedThe security log was wiped. Can be maintenance, but also a defence-evasion tactic.
            4104PowerShell script block loggingShows PowerShell commands that ran, which can reveal scripts executed on the endpoint.
            7045Service installedA new Windows service was created, which can be a normal install or a persistence method.
